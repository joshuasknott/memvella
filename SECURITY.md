# Security Policy

## Reporting Vulnerabilities

Please do not open a public issue for suspected security vulnerabilities.

Use GitHub private vulnerability reporting for this repository if it is enabled.
If private reporting is unavailable, email the public project contact at
`hello@memvella.com` with the subject `Security report`.

Include:

- a concise description of the issue
- affected app, package, route, or function when known
- steps to reproduce with redacted sample data
- the impact you believe the issue may have

Do not include real credentials, production secrets, private health data, or
other sensitive user data in a report.

## Scope

Security reports may cover code in `apps/`, `packages/`, `docs/`, and repository
automation. Public documentation or setup issues that could cause unsafe
deployment are also in scope.

## Response Expectations

Memvella will review reports on a best-effort basis. This repository does not
currently operate a paid bounty program.
